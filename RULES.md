# RULES.md — WiseWorkout Coding Rules for All AI Agents

Before writing any code, read and follow these rules exactly.
See AGENT.md for the full, more detailed version of these rules —
if the two ever disagree, AGENT.md is the source of truth.

## Step 1: Always Check Before Creating

- Run a mental check of existing files first
- Never create a file that already exists
- Never create files outside the lib/ folder unless explicitly told to

## Step 2: Handle These Files With Care

- lib/firebase_options.dart — generated by `flutterfire configure`, gitignored and not tracked in git. Never hand-edit.
- lib/core/app_theme.dart — never modify colors unless explicitly told to
- lib/core/constants.dart — adding new `Collections.x`/`AppConstants` entries here as features need them is normal, expected editing, not something to avoid. Don't restructure or remove existing entries without being asked.
- lib/main.dart — never modify unless explicitly told to
- ios/ and android/ folders — routinely edited for real platform/build-config needs (e.g. Gradle/Kotlin toolchain fixes); avoid unrelated or speculative native changes, but these aren't frozen
- pubspec.lock — never hand-edit directly; it changes automatically via `flutter pub get` whenever pubspec.yaml's dependencies change

## Step 3: Always Follow These Patterns

- Colors: prefer WW.primary, WW.card etc for standard app UI — not absolute in practice (hardcoded colors exist for things like share-card gradient presets), but don't duplicate the same hardcoded value across files; that should become a token instead
- Navigation: always context.go(Routes.x)/context.push(Routes.x) for screen navigation — never Navigator.push. Navigator.pop(dialogContext, result) to dismiss a dialog/bottom sheet is a separate, accepted pattern, not screen navigation.
- Firebase: lib/services/ (FirestoreService/AuthService) is always the default path — a direct Firestore/Auth call in a widget needs a deliberate, documented reason (like coach_screen.dart's message history), not a silent shortcut
- State: setState is the actual dominant, default pattern for screen state — Riverpod is used only for a couple of specific things (routing, the month-activity/streak calendar), not the default for new shared state
- Collection names: never hardcode a collection-name string at a screen/widget call site — the name must live inside firestore_service.dart, either as a Collections.x constant or a private static const field on FirestoreService

## Step 4: When Adding a New Screen

1. Create file in correct lib/screens/subfolder/
2. Add route to Routes class in lib/core/router.dart
3. Add GoRoute entry in routerProvider in lib/core/router.dart
4. Import screen at top of router.dart
5. Exception: the 5 main tab screens (Home/Plans/Coach/Club/Progress) are mounted directly in the app shell's IndexedStack instead of getting their own GoRoute

## Step 5: File Naming

- Files: snake_case → login_screen.dart
- Classes: PascalCase → LoginScreen
- Variables: camelCase → userId
